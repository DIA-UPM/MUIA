# Visual baseline

Reference screenshots of the original site, used by the visual regression tests (`npm run test:visual`). Files: `tests/reference/<page>-<viewport>.png` (full page).

**How they were captured** (`tests/tools/capture-baseline.mjs`, `tests/tools/screenshot.mjs`): Chromium (Playwright), device scale factor 1; sticky header and scroll-to-top button hidden, CSS animations/transitions disabled before the page renders, every image loaded eagerly and decoded, the page scrolled from top to bottom so that lazy content, entrance animations and counters run, then back to the top and captured full-page.

A first capture was made from the live server (kept in `.cache/reference-live-network/`); it showed timing artefacts (some lazy images and sister-site images not yet loaded, Masonry repaints). The final baseline was captured on 2026-10-07 with `--mirror`: the same pages rendered from the crawl cache of the live site (the exact HTML, CSS, JavaScript, fonts and images served by https://muia.dia.fi.upm.es/ that day), which is deterministic and puts no load on the server. For comparison, six 1920 px pages captured both ways differ by 0.00–0.54 % (the sixth, the timetables page, by 5.6 % because the live capture missed its lazy-loaded calendar image).

Viewports: 1920×1080, 1440×900, 1024×768, 768×1024, 390×844. Some original pages are wider than the viewport (e.g. the homepage hero image overflows at every width; timetables and empty tag pages at 390 px); this is visible as a wider screenshot and is reproduced.
